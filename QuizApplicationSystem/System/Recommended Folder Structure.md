# Recommended Swing Folder Structure

## Analysis of the current system

The intended application has three roles: administrators manage accounts and
system records, teachers author quizzes and inspect results, and students take
quizzes and review scores. Shared authentication, subject assignments, quiz
ownership, attempts, scoring, and historical records connect these workflows.

The current implementation is only `Source/QuizoraApp/quizoraApp.java`, whose main
method is empty. `nbproject/project.properties` configures Ant, the `Source` and
`Test` roots, Java 26, and `QuizoraApp.quizoraApp` as the main class. Dependency
classpaths are empty. The workspace has specifications and diagram/flowchart
images, but no Swing screens, JDBC driver, schema scripts, fonts, or tests.
The diagram images remain design references; they have not been validated against
a live database. Existing feature specifications are implementation targets.

A three-layer design with role-grouped UI packages fits this project. It keeps
screens easy to find while sharing business rules and persistence across roles.
Keep the NetBeans/Ant layout with PascalCase source and package folders.
The source root is `Source`, the test root is `Test`, and the package root is
`QuizoraApp`. Build properties now point to those locations.

## Responsibility boundaries

The normal request path is panel/controller -> service -> DAO -> database.
Return plain models or purpose-specific result objects to the presentation layer.
Keep controllers beside their screens; do not make one controller handle every
role and feature. Extract shared UI pieces when actual screens need them.

Services enforce active-account checks, role permissions, ownership, validation,
and assessment rules. DAOs execute prepared SQL and map rows. A service coordinates
multi-DAO transactions using one connection, with commit/rollback at a single
boundary; DAOs must not independently commit parts of the same operation.
Read queries should constrain data to the authorized user or role.

Keep scoring and submission rules in assessmentService so screens cannot award
scores directly. Persist an attempt, its answers, and finalized result consistently;
protect against duplicate submission according to the verified database schema.
Preserve historical results when accounts or quizzes are archived.

Use one JFrame and CardLayout navigation between JPanel screens. This follows
Oracle's [CardLayout guidance](https://docs.oracle.com/javase/tutorial/uiswing/layout/card.html).
Run database work in SwingWorker and update controls on the EDT, following
Oracle's [Swing concurrency guidance](https://docs.oracle.com/javase/tutorial/uiswing/concurrency/index.html).

## NetBeans and resource conventions

- Use PascalCase folders and matching packages such as `QuizoraApp.Ui.Teacher`.
  Use camelCase `.java` and `.form` filenames, such as `loginPanel.java` and
  `loginPanel.form`. Public class names must match their filenames: `loginPanel`.
  This is the project-specific naming convention requested by the owner.
- Keep optional `.form` files beside the corresponding `.java` files.
- Keep `src.dir=Source`, `test.src.dir=Test`, and `main.class=QuizoraApp.quizoraApp`.
- Put assets inside the source root for this Ant layout; load an icon using a
  classpath path such as `/QuizoraApp/Resources/Icons/logo.png`. Verify resources
  are included in the packaged JAR when assets are added.
- `Lib/` is a storage convention, not automatic dependency loading. Add selected
  JARs through NetBeans Libraries so compile/run/distribution classpaths include them.
- Load real database credentials externally; ship only placeholder examples.
- MySQL is the documented persistence target. The live schema needs inspection
  before implementing DAOs or assuming documented migrations exist.

## Suggested implementation order

1. Add the Swing entry-point startup, shared theme, appFrame, and login layout.
2. Configure JDBC and implement authentication, session handling, and role checks.
3. Add dashboard shell navigation and one complete administrator management flow.
4. Implement assigned subjects, quiz authoring, and question validation.
5. Implement student attempts, submission, timing, scoring, and result history.
6. Add dashboard aggregates, teacher statistics, reporting, and remaining profiles.

Validate each complete flow before starting the next. Database-backed checks need
an isolated test database; this workspace currently has no configured test suite.

## Naming examples

```java
package QuizoraApp.Ui.Auth;

public class loginPanel extends javax.swing.JPanel {
    // Future implementation in loginPanel.java
}
```

GUI Builder metadata for this class belongs in `loginPanel.form` in the same
folder. Do not create a `.form` by renaming Java code; create it through NetBeans
GUI Builder when implementing the screen. Empty folders are intentional.
